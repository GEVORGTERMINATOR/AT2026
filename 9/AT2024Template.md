# 1. Введение

## Цели
Документ устанавливает требования к программе лояльности, целью которой является увеличение частоты посещений и лояльности покупателей сети розничных магазинов посредством внедрения системы начисления и списания баллов (оплата товаров), анкеты сбора персональных данных и интеграции с кассовым оборудованием.

## Границы применения
Документ распространяется на программное обеспечение программы лояльности, включая сервис регистрации клиентов, базу данных участников, бэкенд-систему для управления баллами и интерфейс для интеграции с кассовыми терминалами (POS-система).

## Термины и аббревиатуры
**Программа лояльности** — cистема поощрений, которая мотивирует клиентов совершать повторные покупки.  
**Карта лояльности** — уникальный идентификатор участника программы лояльности для накопления баллов.  
**Участник программы** — покупатель, имеющий карту лояльности.  
**Анкета участника** — форма для сбора информации о клиенте при регистрации в программе лояльности.  
**Баллы/бонусы** — условные единицы, начисляемые и списываемые в рамках программы лояльности.  
**Кассовое оборудование** — рабочее место для расчетов с покупателями и проведения операций с баллами программы лояльности.  
**POS-система (Point of Sale)** — кассовая система, предназначенная для регистрации продаж и проведения расчётов с покупателями.  
**Фискальный регистратор** — специализированное устройство, которое используется в контрольно-кассовой технике для фиксации платежных операций, печати чеков и передачи данных о продажах в Федеральную налоговую службу через оператора фискальных данных.  
**Персональные данные** — информация, относящаяся к физическому лицу.

# 2. Общее описание

## Описание изделия
- **Интерфейсы системы**: система взаимодействует с кассами для начисления и списания баллов программы лояльности.
- **Интерфейсы пользователя**:
    - Для администратора: интерфейс для управления программой, настройки стоимости товаров в баллах и количества начисляемых баллов за покупку;
	- Для кассиров: интерфейс для регистрации новых участников, списания и начисления баллов;
- **Интерфейсы аппаратных средств ЭВМ**: касса (POS-система), сканер штрих-кодов, фискальный регистратор, серверное оборудование.
- **Интерфейсы программного обеспечения**: касса (POS-система), СУБД базы участников, бэкенд-система управления баллами, модуль регистрации клиентов.
- **Интерфейсы коммуникаций**: локальная сеть магазина (обязательна для работы с POS), интернет-канал (опционален для критических операций, используется для синхронизации), локальные интерфейсы периферии, платежные системы, учетная система.
- **Ограничения памяти**: на данном этапе не определены.
- **Действия**: работа кассира с покупателем во время расчёта, операции администратора (настройка параметров товаров, акций, просмотр отчётов).

## Функции изделия
- Выдача и регистрация карт лояльности.
- Заполнение анкеты при выдаче карты.
- Начисление баллов за покупки.
- Списание баллов для оплаты товаров.
- Управление данными участников и товаров.
- Настройка сотрудником магазина параметров товара: сколько баллов начисляется при покупке и за сколько баллов товар можно купить.
- История операций с баллами.
- Интеграция с кассовым оборудованием и POS-системой.
- Предоставление покупателю баланса баллов через мобильное приложение.
- Формирование отчётности по программе лояльности.

## Характеристики пользователей
- Покупатели (участники программы): заполняют анкету при регистрации карты, предъявляют карту при покупке, копят и тратят баллы.
- Кассиры: регистрируют новых участников, заполняют анкету, сканируют карты, проводят операции с баллами через POS. Нужно базовое обучение.
- Администраторы магазина: настраивают баллы за товары, стоимость товаров в баллах, акции, смотрят отчёты. Нужны навыки работы с аналитикой.

## Ограничения
- В связи с отсутствием в POS-системе поддержки баллов необходима разработка модуля интеграции.
- Товар оплачивается только рублями или только баллами, частичная оплата не предусмотрена.
- Обработка персональных данных ведется в соответствии с требованиями [152-ФЗ] (анкета клиента включает: пол, день и месяц рождения без указания года, социальное положение, район проживания без номера дома).

## Предположения и зависимости
- Все товары в магазине имеют две характеристики:
    - Количество баллов, которое начисляется за покупку товара;
    - Количество баллов, которые можно потратить на покупку товара.
- Каждый участник программы имеет карту и уникальный идентификатор.
- Сотрудники магазина будут предлагать программу лояльности покупателям.
- При выдаче карты предлагается заполнить анкету, в которой указываются:
    - пол;
    - день и месяц рождения без указания года;
    - социальное положение;
    - район проживания без номера дома.

# 3. Детальные требования

## Атрибуты требования
Каждое требование имеет следующие атрибуты:
- ID — уникальный идентификатор требования.
- Название — название функции системы, к которой предъявляются требования.
- Описание — описание требования.
- Приоритет — важность реализации требования. Чем меньше число, тем выше приоритет.
- Стабильность — вероятность изменения требования в будущем (стабильно/ вероятны изменения/нестабильно).

## Функциональные требования
**ID:** R1.01.01  
**Название:** Регистрация карты лояльности клиенту  
**Описание:** Позволяет сотруднику зарегистрировать выданную карту и связать её с участником.  
**Приоритет:** 1  
**Стабильность:** Стабильно  

**ID:** R1.01.02  
**Название:** Идентификатор карты лояльности  
**Описание:** Каждая карта лояльности должна иметь уникальный номер. Номер карты должен храниться в базе данных системы.  
**Приоритет:** 1  
**Стабильность:** Стабильно  

**ID:** R1.01.03  
**Название:** Анкета при выдаче новой карты  
**Описание:** Заполнение анкеты покупателем при регистрации новой карты лояльности. Анкета должна содержать следующие поля: пол, день и месяц рождения без указания года, социальное положение и район проживания без номера дома.  
**Приоритет:** 1  
**Стабильность:** Вероятны изменения  

**ID:** R1.01.04  
**Название:** Привязка карты к клиенту  
**Описание:** Карта лояльности должна быть привязана к одному и только одному клиенту.  
**Приоритет:** 1  
**Стабильность:** Стабильно  

**ID:** R1.01.05  
**Название:** Блокировка карты  
**Описание:** Система должна позволять сотруднику магазина заблокировать карту по заявлению клиента.  
**Приоритет:** 2  
**Стабильность:** Стабильно  

**ID:** R1.01.06  
**Название:** Перевыпуск карты  
**Описание:** При перевыпуске карты система должна присваивать участнику новый номер карты с сохранением накопленных баллов. Предыдущая карта после перевыпуска должна блокироваться.  
**Приоритет:** 2  
**Стабильность:** Стабильно  

**ID:** R1.02.01  
**Название:** Настройка параметров балльной программы  
**Описание:** Администратор должен иметь возможность задавать: количество начисляемых баллов за товар и количество баллов для оплаты товара.  
**Приоритет:** 1  
**Стабильность:** Нестабильно  

**ID:** R1.02.02  
**Название:** Начисление баллов за покупку  
**Описание:** При покупке товара с предъявлением карты лояльности система должна начислять участнику количество баллов, установленное для данного товара.  
**Приоритет:** 1  
**Стабильность:** Стабильно  

**ID:** R1.02.03  
**Название:** Списание баллов за покупку  
**Описание:** Система должна предоставлять возможность оплаты товара баллами по стоимости, установленной для данного товара. Перед списанием баллов система должна проверять достаточность баланса участника. Если баллов недостаточно, оплата баллами не выполняется.  
**Приоритет:** 1  
**Стабильность:** Стабильно  

**ID:** R1.02.04  
**Название:** Баланс баллов  
**Описание:** Система должна хранить текущий баланс баллов клиента.   
**Приоритет:** 1  
**Стабильность:** Стабильно  

**ID:** R1.02.05  
**Название:** Оплата одним номиналом  
**Описание:** Каждый товар может быть оплачен либо полностью рублями, либо полностью баллами. Частичная оплата одного товара рублями и баллами не допускается.  
**Приоритет:** 1  
**Стабильность:** Вероятны изменения  

**ID:** R1.02.06  
**Название:** История операций с баллами  
**Описание:** Система должна хранить историю начислений и списаний баллов с указанием даты, времени, суммы покупки и количества баллов.  
**Приоритет:** 2  
**Стабильность:** Стабильно  

**ID:** R1.02.07  
**Название:** Обработка возврата товара  
**Описание:** При возврате товара система должна пересчитывать начисленные и списанные баллы.  
**Приоритет:** 3  
**Стабильность:** Стабильно  

**ID:** R1.03.01  
**Название:** Обмен данными с POS  
**Описание:** Система должна обеспечивать обмен данными с кассовым оборудованием (POS-терминалами).  
**Приоритет:** 1  
**Стабильность:** Стабильно  

**ID:** R1.03.02  
**Название:** Считывание карты на POS  
**Описание:** При предъявлении карты лояльности POS-терминал должен передавать в систему ID карты.  
**Приоритет:** 1  
**Стабильность:** Стабильно  

**ID:** R1.03.03  
**Название:** Передача содержимого чека  
**Описание:** После оформления покупки POS-система должна передавать сведения о приобретённых товарах и их количестве для расчёта начисляемых баллов.  
**Приоритет:** 1  
**Стабильность:** Стабильно  

**ID:** R1.03.04  
**Название:** Запрос на списание баллов  
**Описание:** При оплате баллами POS-терминал должен передавать в систему запрос на списание баллов.  
**Приоритет:** 1  
**Стабильность:** Стабильно  

**ID:** R1.03.05  
**Название:** Ответ системы на POS  
**Описание:** Система должна возвращать на POS-терминал результат операции: успех, отказ, доступный баланс.  
**Приоритет:** 1  
**Стабильность:** Стабильно  

**ID:** R1.03.06  
**Название:** Автономный режим POS  
**Описание:** При отсутствии связи с системой лояльности POS-система должна сохранять сведения о покупках, оплаченных рублями, для последующей обработки и начисления баллов. Списание баллов при отсутствии возможности проверить актуальный баланс не допускается.  
**Приоритет:** 2  
**Стабильность:** Вероятны изменения  

**ID:** R1.03.07  
**Название:** Защита от дублирования операций  
**Описание:** Повторная передача одной и той же операции с POS не должна приводить к двойному начислению или списанию.  
**Приоритет:** 1  
**Стабильность:** Стабильно  

## Надежность
- **Доступность**: не менее 99% в течение календарного месяца.
- **MTBF**: не менее 20000 часов.
- **MTTR**: не более 20 минут.
- **Точность**: не менее 99% корректных начислений и списаний баллов.
- **Макс. количество ошибок**: не более 3 критических дефектов во время промышленной эксплуатации.

## Производительность
- **Время отклика**: не более 2 секунд для операций с баллами на кассе и для работы с веб-интерфейсом.
- **Пропускная способность**: не менее 2000 операций в минуту без потери данных.
- **Утилизация ресурсов**: при штатной нагрузке использование ЦПУ не больше 70%, памяти - не больше 80%.

## Ремонтопригодность
- Система должна позволять изменять правила начисления и списания баллов без изменения функций регистрации участников и взаимодействия с кассовым оборудованием.
- Обновления осуществляются без остановки системы с возможностью отката. Тестовый режим позволяет проверять изменения
- Осуществляется версионирование правил и настроек, сохраняется история изменений, существует возможность отката. 

## Ограничения проекта
- Интернет-канал используется для синхронизации с центральным сервером и обновлений.
- Допускается использование только стандартизированных протоколов интеграции с POS.
- Для каждого товара должны быть предусмотрены параметры начисления баллов за покупку и стоимости товара в баллах. Значения этих параметров задаются уполномоченным сотрудником магазина.
- Оплата товара возможна только полностью за рубли или полностью за баллы. Смешанная оплата не допускается.
